## 1. OpenTelemetry JS SDK 2.0 — Browser Frontend Tracing

### What changed
- **OTel JS SDK 2.0** (March 2025) — stable browser tracing, smaller bundles, ES2022 target
- Dedicated **Browser SIG** formed (late 2025) improving tree-shaking, event-based instrumentations
- New `open-telemetry/opentelemetry-browser` repo for navigation timing, resource timing, user actions, web vitals, console
- Packages: `@opentelemetry/sdk-trace-web`, `@opentelemetry/auto-instrumentations-web`

### For Anvil
Phase 20 already has OpenTelemetry distributed tracing. The browser SDK 2.0 enables **frontend-to-backend trace correlation** — trace a user click through the API, DB, and S3. The new browser-specific repo adds Web Vitals instrumentation for the performance monitoring dashboard.

**Action**: Add `@opentelemetry/auto-instrumentations-web` to all Anvil frontends for end-to-end trace correlation. Export to existing OTel collector. This completes Phase 20's distributed tracing item.

## 2. Drizzle ORM — TypeScript-First PostgreSQL ORM

### Status (2025–2026)
- Lightweight, zero code-gen, SQL-like TypeScript API
- Native PostgreSQL: RLS, JSONB operators, lateral joins, partitioned tables
- v1.0.0-beta.2 (Feb 2025) with improved migration engine, relational queries v2
- Stable line (0.44–0.45.x) production-ready
- Drivers: `pg`, `postgres.js`, Neon, Supabase, Vercel Postgres, PGlite (WASM)
- Drizzle Studio GUI for schema inspection + SQL console

### For Anvil
Currently using raw SQL + Prisma(?). Drizzle offers:
- Full type safety without code generation
- Edge/serverless compatible (works with PGlite for offline)
- RLS support aligns with multi-tenancy (Phase 26)
- Drizzle Kit migrations are SQL-based (inspectable, versionable)

**Action**: Evaluate Drizzle ORM for new services. Particularly useful for the Drive and Search backends where type-safe SQL queries would reduce errors. PGlite (WASM) support pairs with offline-first efforts.

## 3. Playwright Component Testing + Visual Regression

### Status
- Component testing mounts React/Vue/Svelte components in real browser
- `toHaveScreenshot()` for pixel-level visual regression
- Cross-browser: Chromium, Firefox, WebKit
- Tolerance options: `maxDiffPixels`, `maxDiffPixelRatio`
- Still marked "experimental" but production-ready and widely used

### For Anvil
Phase 20 has "Visual regression testing in CI" unchecked. Playwright component testing with `toHaveScreenshot()` is the simplest path — no extra dependencies beyond the existing Playwright setup.

**Action**: Implement visual regression using existing Playwright setup. Add `toHaveScreenshot()` to component tests for `@anvil/ui` shared components. Commit snapshot baselines to git.

## 4. Tauri 2.0 — Desktop App Framework

### Status (2025–2026)
- Stable since Oct 2024, v2.10.1 (March 2026)
- Uses system webview (WebView2 on Windows, WKWebView on macOS, WebKitGTK on Linux)
- 5–20 MB binaries vs Electron's 100+ MB
- Multi-webview support, system tray, native menus, file access, auto-updater
- Mobile support (Android/iOS) from same codebase
- Granular capability-based security model

### For Anvil
Phase 25 already has "Tauri 2.0 desktop app" unchecked. Tauri is now mature with v2.10+ stable. System webview means the Next.js frontends render natively without bundling Chromium. The 5–20 MB binary is a strong selling point for the portfolio.

**Action**: Tauri 2.0 is ready for Phase 25 implementation. Multi-webview could enable running all 6 Anvil apps in one desktop window with tab switching.

## 5. Zitadel — Third IAM Option

### What
- Cloud-native, Go-based IAM (vs Keycloak's Java, Authentik's Python)
- Built-in multi-tenancy, passkeys/passwordless, audit trails
- API-first: Terraform provider, gRPC, REST
- v3 (2025): switched to PostgreSQL (removed CockroachDB dep), AGPL-3.0 license
- v4 GA: new APIs, SDKs, Login v2
- Free self-hosted + optional cloud tier

### Comparison for Anvil

| | Keycloak | Authentik | Zitadel |
|---|---|---|---|
| Language | Java | Python | Go |
| Resource usage | Heavy | Moderate | Light |
| Multi-tenancy | Basic | Basic | Excellent |
| Passkeys | Add-on | Built-in | Built-in |
| License | Apache 2.0 | MIT | AGPL-3.0 |
| Best for | Enterprise | Self-hosted | Cloud-native |

**Action**: Add Zitadel as a third IAM evaluation option alongside Authentik. Best fit if Anvil pursues multi-tenant SaaS (Phase 26). AGPL license is a consideration for any commercial use.
