## 1. Mediasoup vs LiveKit — WebRTC SFU for Video Calling

### Mediasoup v3.19 (Node.js SFU)
- Actively maintained, v3.19.22 stable
- Simulcast, SVC, AV1 Dependency Descriptor forwarding
- `useBuiltInSctpStack` option for DataChannel improvements
- Node.js ≥22 required, C++20, Rust port available (v0.20)
- Full control over producers/consumers/routers — low-level, flexible
- PipeTransport for multi-server scaling

### LiveKit v1.12 (Go SFU, Apache 2.0)
- Self-hostable or managed cloud
- **LiveKit Agents** framework (Python/JS) for AI voice/video agents
- Used by OpenAI for ChatGPT Voice
- Browser-based Agent Builder, SIP telephony integration
- Complete stack: server + client SDKs (web/mobile) + agents + observability
- Higher-level API than mediasoup — faster to build, less fine-grained control

### Recommendation for Anvil (Phase 24)
Phase 24 currently lists "mediasoup SFU" for multi-party calling.

- **LiveKit** is the better choice for Anvil's portfolio — faster to implement, more features out-of-box (agents, SIP, mobile SDKs), and the AI agents framework could power voice-driven features across all apps.
- **Mediasoup** is better if you need maximum control over media routing or want to demonstrate low-level WebRTC expertise.

**Action**: Consider LiveKit as the primary SFU for Phase 24. Keep mediasoup as an alternative for a "deep dive" implementation.

## 2. PGlite v0.4 — WASM PostgreSQL in the Browser

### What
- Full PostgreSQL compiled to WASM, under 3 MB gzipped
- Runs entirely in browser, persisted to IndexedDB
- **pgvector built-in** — vector search directly in the browser
- **PostGIS support** (new in v0.4, March 2026) — geospatial queries in browser
- **Live queries** — reactive subscriptions to query results
- Connection multiplexing (v0.4) — multiple connections in one tab
- `@electric-sql/pglite-sync` plugin (alpha) for server sync
- 13M+ weekly npm downloads

### For Anvil
This is significant. Instead of choosing between SQLite (Turso/PowerSync) and IndexedDB (Dexie.js) for offline storage, PGlite gives you **the same PostgreSQL dialect** locally that runs on the server. Benefits:

- **Drive**: Full SQL file metadata queries offline with pgvector for semantic search
- **Docs**: Document metadata + search offline
- **Maps**: PostGIS geospatial queries client-side (eliminates need for server round-trips for POI search)
- **Search**: pgvector enables local semantic search without a server
- **Gmail**: Email metadata cache with full SQL queries

Schema parity between server (Neon/PostgreSQL) and client (PGlite) means zero translation layer.

**Action**: Evaluate PGlite as the unified client-side database for offline features. PostGIS in-browser is a unique capability for the Maps clone. Higher priority than Dexie.js/Turso for offline strategy.

## 3. Vercel AI SDK 5→6 — Streaming RAG & Agents

### AI SDK 5 (July 2025)
- Redesigned chat primitives, agentic loop control
- Data parts for streaming custom payloads
- SSE-based streaming

### AI SDK 6 (December 2025)
- **Agent class** (`ToolLoopAgent`) for reusable, tool-using agents
- Type-safe call options for injecting RAG context per request
- Unified tool + structured output handling
- `stopWhen: stepCountIs(n)` for multi-step loops

### Official RAG Template
- Next.js + AI SDK + Drizzle ORM + PostgreSQL + pgvector
- `streamText` + `useChat` for real-time streaming
- ~20 lines vs 100+ with LangChain

### For Anvil (Phase 13)
The `@anvil/ai` package could leverage Vercel AI SDK internally:
- **Copilot sidebar**: Use `useChat` for streaming responses
- **Document intelligence**: Tool-using agents for auto-TOC, style matching
- **Email categorization**: RAG agent with email context
- **Cross-app search**: RAG with pgvector results from Drive/Docs/Gmail

**Action**: Evaluate Vercel AI SDK as the foundation for `@anvil/ai`. Drastically simplifies streaming UI integration vs building custom SSE handling. The official RAG template aligns with the existing pgvector + HNSW setup.

## 4. tRPC v11 — End-to-End Type Safety

### Status (March 2025 stable, v11.17.0 April 2026)
- No code generation, no schemas — types inferred from server procedures
- First-class Next.js App Router + RSC support (v11 improvement)
- Native TanStack React Query v5 integration
- Streaming, Suspense, server-side prefetching
- Zod for input/output validation

### For Anvil
Phase 9 uses OpenAPI 3.1 contract-first with `@hey-api/openapi-ts`. tRPC v11 offers an alternative:

| | OpenAPI + codegen | tRPC v11 |
|---|---|---|
| Type safety | Via generated client | Automatic inference |
| Boilerplate | Schema + client gen | None |
| External API | Yes (Swagger/Scalar) | No (internal only) |
| Learning curve | Standard REST | TypeScript-only |
| Next.js RSC | Manual setup | Native support |

**Action**: tRPC could replace the internal API client for frontend↔backend communication while keeping OpenAPI for external/public API (Phase 17). Best of both worlds: tRPC for internal speed, OpenAPI for public docs.
