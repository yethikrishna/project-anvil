## 1. Hocuspocus v4.0 (April 2026) — Docs Collaboration Backend

Major stable release of the Yjs WebSocket server used in the Docs clone:

- **Cross-runtime**: Node.js, Bun, Deno, and **Cloudflare Workers** via `crossws`
- **Memory optimization**: Yjs update messages encoded once, shared across connections
- **Better persistence hooks**: `onLoadDocument` accepts raw `Uint8Array`, `onStoreDocument` triggers on any change
- **Stronger TypeScript**: Generic `Context` typing throughout
- **Awareness/presence improvements**: `beforeHandleAwareness` hook (v4.1.0, released today)
- **Edge deployment**: Can now run on Cloudflare Workers — enables global low-latency collab

**Action**: Upgrade Docs clone's Hocuspocus to v4 for memory savings and edge deploy capability. Cloudflare Workers deployment could eliminate the Render backend for collab.

## 2. MapLibre GL JS — MLT Format & v6 Preview

### MapLibre Tile (MLT) — New vector tile format
- Successor to MVT (Mapbox Vector Tiles)
- **Up to 6× smaller tiles** for polygon/line data
- Optimized for modern GL/WebGL rendering
- Native support in MapLibre GL JS v5.12.0+ via `encoding: "mlt"`
- Served via Martin tile server

### v6.0.0 Pre-releases (April–May 2026)
- **Drops WebGL 1** (WebGL 2 required) — better perf, easier WebGPU future
- **ESM-only** distribution
- Terrain 3D performance optimizations

**Action**: Evaluate MLT format for Maps clone — 6× smaller tiles = faster loads + lower bandwidth. Martin tile server supports MLT natively. Pin to v5.x for now; plan v6 migration when stable.

## 3. WebRTC P2P File Sharing

For the Phase 15 WebRTC P2P file sharing feature:

- **simple-peer** — lightweight WebRTC wrapper, widely used, DTLS-encrypted by default
- **PeerJS** — higher-level abstraction, beginner-friendly, supports file/blob sending
- **WebTorrent** — browser BitTorrent via WebRTC, supports multi-peer large file transfers
- **RxDB WebRTC Replication** — P2P database sync across browsers using simple-peer

All connections are **DTLS-encrypted by default**. For additional E2EE, add an AES layer on top.

**Action**: Recommend **PeerJS** for the Drive clone's P2P sharing feature (simplest API, handles signaling). For multi-peer/large files, consider WebTorrent.

## 4. Next.js 16 — Cache Components & Streaming

Released October 2025. Key improvements for Anvil's Next.js 15 apps:

### Cache Components (PPR evolved)
- `"use cache"` directive for explicit granular caching
- Static shell + dynamic streamed portions via Suspense
- New APIs: `revalidateTag()` with cache life profiles, `updateTag()` for read-your-writes

### Performance
- **Turbopack** stable and default bundler — 2–5× faster builds, 10× faster Fast Refresh
- Async params/searchParams/cookies (sync access removed)
- Better prefetching and layout deduplication

**Action**: Plan migration from Next.js 15 → 16 for all frontend apps. Cache Components would benefit Drive (file listings), Gmail (inbox), and Search (results). Turbopack speeds up dev iteration significantly.

## 5. Local-First Architecture Patterns

Maturing rapidly in 2025–2026. Key patterns applicable to Anvil:

### Sync Engines
- **PowerSync** — bidirectional sync (SQLite ↔ PostgreSQL/MongoDB), offline reads+writes, persistent upload queue. Supabase integration, Rust SQLite core. Added SQL Server support Jan 2026.
- **ElectricSQL** — Postgres-to-client real-time sync via shapes/partial replication. CRDT-based. Good for read-heavy dashboards.

### Local-First Patterns
1. **Client-as-source-of-truth**: Local DB first, sync in background
2. **Optimistic updates + CRDT conflict resolution**
3. **Durable local storage**: IndexedDB, SQLite via WASM (sql.js)
4. **Background sync via Service Workers**
5. **Schema evolution across devices**

**Action**: PowerSync + local SQLite could enable true offline for the Drive and Docs clones. Consider for Phase 15's "Full offline PWA with Workbox" item.
