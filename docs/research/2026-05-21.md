## 2. Turso / libSQL — Edge SQLite with Embedded Replicas

### What
- Distributed edge database built on libSQL (open-source SQLite fork)
- **Embedded Replicas**: Full local SQLite replica in-app with microsecond reads + automatic cloud sync
- April 2026: Major Rust rewrite of SQLite engine recommended over legacy libSQL SDKs
- Supports Node.js, Bun, Go, Rust, Python

### Why for Anvil
- Could replace Neon PostgreSQL for apps needing edge latency
- Embedded replicas enable true offline for Drive/Docs (local SQLite + sync)
- Free tier: 9GB storage, 500 databases, 1 billion row reads/month
- Works with Prisma, Drizzle, Remix, Next.js

**Action**: Evaluate Turso embedded replicas for offline Drive/Docs as an alternative to PowerSync. Simpler architecture (SQLite native, no separate sync engine).

## 3. Bun + Elysia — Production-Ready Backend Stack

### Bun Runtime (1.3+, 2025–2026)
- ~98% Node/npm compatibility
- `Bun.serve()` at ~180k req/s vs Fastify ~55–95k req/s
- 8–15ms cold starts vs Node's 40–120ms
- Vercel added native Bun support for Next.js (late 2025)
- Official Docker, K8s, systemd deployment guides

### ElysiaJS (Bun-native framework)
- First production-ready Bun framework
- ~2.45M req/s in plaintext benchmarks
- End-to-end TypeScript type inference (tRPC-like without client-server split)
- **Auto-generated OpenAPI docs** from routes
- Plugins: auth, validation, WebSocket, Drizzle/Prisma
- Single binary compilation (`bun build --compile`) for deployment
- State of JS 2025 standout

**Action**: Consider Elysia + Bun as a Fastify replacement for new backend services. Auto-generated OpenAPI aligns with Phase 9's contract-first API spec. Would need migration for existing Express/Fastify backends.

## 4. FFmpeg.wasm — Browser Video Processing

### Status (2025–2026)
- Actively maintained, v12.15 (main branch)
- Supports: H.264/H.265, VP8/VP9, MP3, Opus, subtitles, WebP
- Client-side transcoding — no server upload required
- Works with **WebCodecs API** for hardware-accelerated decode/encode pipeline
- Limitation: CPU-only (no GPU via WASM), slower for 4K/large files

### For YouTube Clone
- Client-side video re-encoding before upload (reduce bandwidth)
- Thumbnail extraction in-browser
- Video trimming/editing UI
- Format conversion (MOV→MP4, etc.)

**Action**: Integrate FFmpeg.wasm for client-side video preprocessing in YouTube clone upload flow. Reduces server-side transcoding costs.

## 6. Dexie.js v4 — IndexedDB for Offline-First

### Status
- v4.4.x, actively maintained
- `dexie-react-hooks` provides `useLiveQuery` — auto re-renders on DB changes
- Schema versioning, migrations, transactions
- TypeScript `EntityTable` typing
- Optional **Dexie Cloud** for real-time sync + auth

### For Offline Drive/Docs
- Local file metadata cache for Drive (instant folder listing offline)
- Document drafts for Docs (write offline, sync when online)
- Email drafts for Gmail
- Works in Service Workers for background sync

**Action**: Use Dexie.js as the client-side IndexedDB layer for all offline-first features. Simpler than full PowerSync/Turso for read-heavy caches. Pairs well with Service Workers.
