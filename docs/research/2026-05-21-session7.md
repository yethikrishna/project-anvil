# Research Report — 2026-05-21 Session 7 (08:06 UTC)

## 1. Google Workspace Alternative Landscape (2026)

### Self-Hosted Suite Players
| Google Service | Best OSS Alternative | Notes |
|---|---|---|
| Drive | **Nextcloud** / **Seafile** | Nextcloud = full suite; Seafile faster for large files |
| Docs/Sheets/Slides | **Nextcloud + OnlyOffice** / **Collabora** / **CryptPad** | CryptPad = E2EE; OnlyOffice best MS compat |
| Gmail | **Stalwart** / **Mailcow** / **Mailu** | Stalwart = JMAP-native; Mailcow = traditional IMAP |
| YouTube | **PeerTube** | ActivityPub federation, live streaming, channels |
| Maps | **OSM stack** (PMTiles + Protomaps + MapLibre) | Static tiles, no tile server needed |
| Search | **SearXNG** (meta) / **Meilisearch** (app data) | SearXNG for web search; Meilisearch for app search |

### Key Takeaway
Anvil's approach (building each clone from scratch with modern stack) is the right portfolio strategy. Nextcloud et al are deployment targets, not competitors — we showcase *how to build* these tools.

## 3. IAM/SSO Comparison (2026)

| Aspect | Keycloak | Authentik 2026.2 | Zitadel |
|---|---|---|---|
| Language | Java/Quarkus | Python 3.14 + TS | Go |
| Setup Complexity | High | Medium | Medium |
| Multi-Tenancy | Realms (complex) | Good | **Native** |
| Redis Required | Yes | **No** (dropped) | No |
| License | Apache 2.0 | MIT core | AGPL-3.0 |
| Best For | Enterprise/regulated | Self-hosted/teams | B2B SaaS |

### Authentik 2026.2 Highlights
- Dropped Redis dependency (big ops win)
- Python 3.14 backend
- SCIM policy-based sync filtering, WS-Federation (Enterprise)
- Object Lifecycle Management (Enterprise)

### Other Options
- **Authelia** — lightweight forward-auth for homelab (MFA + SSO)
- **Ory Stack** (Kratos + Hydra) — headless, API-first, microservices-friendly

**Action**: Authentik is the best Keycloak replacement for Anvil's self-hosted story (no Redis, simpler Docker, MIT license). Zitadel worth evaluating for multi-tenant features.

## 4. CRDT Libraries (2026 State)

| Metric | Loro | Yjs | Automerge |
|---|---|---|---|
| Apply (260K ops) | **~290ms** | ~430ms | ~680ms |
| Encode/Decode | **2-5ms** | 4-8ms | 12-45ms |
| Memory | **~15MB** | ~20MB | ~41MB |

**Recommendation**: Keep Yjs for editor bindings maturity. Evaluate Loro for Docs versioning/time-travel features. The gap is closing fast.

## 6. PMTiles + Protomaps (Maps Stack)

- Single `.pmtiles` file = entire tile pyramid (Hilbert-ordered)
- HTTP Range requests → no tile server needed
- Daily-updated planet builds (~100-120 GB)
- `pmtiles extract` CLI for regional extracts
- Works with S3, Cloudflare R2, Supabase Storage, GitHub Pages
- MapLibre GL + `pmtiles.js` plugin for rendering

**Action**: Replace custom tile server with PMTiles for demo deployment. Regional extract for demo (India/US). Eliminates tile server infrastructure.

## 7. PGlite v0.4+ (WASM Postgres)

- ~2.6-3 MB gzipped, full Postgres 17 in WASM
- Supports **pgvector**, **PostGIS**, live queries
- IndexedDB persistence in browser, filesystem in Node/Bun/Deno
- ElectricSQL sync plugin for real-time replication
- Used by Supabase `database.build`

**Action**: Strong candidate for offline Drive/Docs. Evaluate for client-side search index (pgvector + HNSW in browser).
