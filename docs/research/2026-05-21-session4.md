## 1. TanStack Table v9 (Alpha) — Headless Data Grid

### Status
- v9.0.0-alpha.49 (May 19, 2026) — not yet stable, v8 remains production
- Tree-shakable features: import only pagination/sorting/filtering needed
- Base bundle ~4–7 KB vs v8's 14–20 KB
- `useReactTable` → `useTable`, `get*RowModel` → `create*RowModel`
- New utilities: `tableOptions()`, `createTableHook()`, `tableFeatures()`
- Server-side data via TanStack Query v5 works identically to v8

### For Anvil
Drive (file listings), Gmail (inbox), Docs (document list), and Search (results) all use data grids. TanStack Table v8 or the upcoming v9 would provide consistent, headless table primitives across all apps with virtualized scrolling for large datasets.

**Action**: Adopt TanStack Table for all list/grid views across Anvil apps. Stay on v8 for now, plan v9 migration when stable. Pairs with TanStack Query v5 for server-side data.

## 2. Zod v4 — Schema Validation

### Status (stable mid-2025, v4.4.x May 2026)
- **14× faster** string parsing, **7× faster** arrays, **6.5× faster** objects vs v3
- Bundle size roughly halved; `@zod/mini` variant for edge/frontend
- Built-in JSON Schema conversion (`z.toJSONSchema`)
- Native file validation, i18n/locales, metadata/registry
- JIT compilation for repeated validation

### For Anvil
Zod is already likely used with tRPC/Elysia. v4's performance gains matter for:
- API request validation on every endpoint
- Form validation across all frontends
- `@zod/mini` for edge-deployed functions (CF Workers)

**Action**: Upgrade to Zod v4 across all packages. Use `@zod/mini` for edge/frontend validation where bundle size matters.

## 3. Service Worker + Background Sync — Offline POSTs

### Status
- Background Sync API: Chrome/Edge only (no Safari/Firefox)
- Workbox `workbox-background-sync` remains the production standard
- Queue failed POST/PUT/DELETE requests, auto-replay when online
- `maxRetentionTime` prevents infinite retries
- Periodic Background Sync still experimental

### For Anvil
Phase Backlog has "Full offline PWA with Workbox". Implementation path:
1. Workbox for asset caching (static shell)
2. Background Sync for API mutations (create file, send email, save doc)
3. Dexie.js/PGlite for read data offline
4. Combined: full offline read+write experience

**Action**: Implement Workbox Background Sync for all mutation endpoints. Chrome-only is acceptable as progressive enhancement.

## 4. Valkey — Open-Source Redis Replacement

### What
- Fork of Redis 7.2.4 (BSD license) after Redis changed to non-open-source licensing
- Backed by AWS, Google, Oracle under Linux Foundation
- v9.0.x (May 2026) — I/O multi-threading, dual-channel replication
- 20–40% better memory efficiency, 230%+ throughput gains in benchmarks
- Drop-in Redis compatible (RESP protocol, same clients)
- Managed on AWS ElastiCache, GCP Memorystore, OCI, DigitalOcean

### For Anvil
Phase 1 uses Redis. Valkey is a license-safe, often faster replacement:
- Session storage
- Rate limiting
- Caching layer
- No vendor lock-in, truly open-source (BSD 3-Clause)

**Action**: Replace Redis with Valkey in Docker Compose. Same client libraries work — just swap the image. Zero code changes needed.

## 5. Hono — Edge Framework for Cloudflare Workers

### Status (v4.12.x, May 2026)
- ~402K ops/sec on CF Workers, <14 KB bundle
- Multi-runtime: CF Workers, Deno, Bun, Vercel Edge, Node.js
- Zero dependencies, Web Standards only
- Official CF recommendation for Workers APIs
- Rich middleware: Zod validation, JWT, rate limiting, OpenAPI/Swagger
- `@hono/zod-validator`, `@hono/swagger-ui`

### For Anvil
Phase Backlog has "Edge computing (Cloudflare Workers / Vercel Edge) for auth + caching". Hono is the ideal framework:
- Auth middleware at the edge (verify JWT, redirect)
- API caching layer at the edge (cache Meilisearch results, Drive metadata)
- Rate limiting at the edge (before hitting backend)
- Could replace the need for a separate backend for lightweight API routes

Compared to Elysia (Bun-only), Hono runs everywhere including edge. Could serve as the edge gateway while Elysia handles heavy backend work.

**Action**: Evaluate Hono as the edge gateway for Anvil. One codebase for CF Workers edge + Bun backend. Pairs with Zod v4 for validation.
